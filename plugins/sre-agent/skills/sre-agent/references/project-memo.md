# Project Context Memo

Phase 0 reads this to warm-start; the write-back happens at **end of run**
(after investigation), not during discovery. The memo lives at
`docs/sre-agent-memo.md` in the repo the agent is invoked in. It is a
**curated, service-centric** distillate of discovery — durable structure only,
never a full object inventory (those stay a live `kubectl get` away).
Everything the memo records is metadata; **never a secret value**.

## Memo schema

```markdown
# SRE Agent Memo — <project/repo name>
_Last verified: <YYYY-MM-DD> · Generated by sre-agent. No secrets — metadata only._

## 1. Environments
| Env | Cluster / context | Cloud acct | Region | Key namespaces | Notes / limitations |

## 2. Observability
| Component | Access (svc / port-forward cmd / URL) | Auth source | Status |
Components: Prometheus, Alertmanager, Grafana, Loki, Tempo/Jaeger,
Elasticsearch/OpenSearch, CloudWatch.
"Auth source" = pointer only (e.g. "token in Vault kv/obs/grafana",
"AWS Secrets Manager arn:…"). "Status" = ✓ verified <date> | ⚠ needs verification | ✗ not present.

## 3. Service map
### <service>
- Namespace / Deployment / Service / Ingress-or-endpoint / recorded image tag
- GitOps manager (Flux / Argo CD / none) — re-verify before any fix (Safety rule 5)
- Dashboards · Alerts · Log source (LogQL/index) · Traces
- Repo · CI/CD pipeline
- Owner / dependencies

## 4. Changelog
- <date> — <structural change> (new/removed workload, image bump, ingress/ns/ownership/dep change, obs link change)

## 5. Discovery history
- <date> — scanned: <scope> · reused: <what> · changed: <what> · needs verification: <what>

## 6. Known unknowns
- <fact marked needs-verification> — why (no access / ambiguous / not yet investigated)
```

Two rules keep it high-signal:

- **Section 3 grows by investigation, not by cluster scan.** A service enters
  the map the first time the agent works on it — not by enumerating everything.
- **Every §1/§2 row carries a `Status` marker.** The freshness check reads and
  stamps these, so "verified vs assumed" is never guesswork.

## Fast freshness check

Cheap, read-only, bounded. Proves what still exists without full re-discovery.
Best-effort: if `kubectl` or an endpoint is unreachable, mark the fact
`⚠ needs verification` — **never delete on a single failed check**.

**Pin the context.** Every `kubectl` command below must target the memo row's
recorded context (`--context <ctx>`), never the current default context — a
multi-environment memo (§1) otherwise queries the wrong cluster and produces
false results. **Query one name at a time**, not a batched list or a
`deploy,sts,ds` resource-type cross-product: a batch call errors and exits non-zero on
the first missing name, which would wrongly fail every fact in the batch.

| What | Command (per item, per its recorded context) | Pass = |
| :--- | :--- | :--- |
| Clusters/contexts | `kubectl config get-contexts -o name` | memo context still listed |
| Namespaces | one call per namespace: `kubectl --context <ctx> get ns <name>` | namespace still exists |
| Service-map workloads | one call per workload, its **recorded type only**, with the image visible: `kubectl --context <ctx> -n <ns> get deploy/<name> -o wide` (or `sts/<name>`, `ds/<name>`; or `-o jsonpath='{..image}'`) | workload present **and** image tag matches the memo — a differing tag is a verified change (flag drift, → §4 Changelog) |
| Obs endpoints | component-specific health check against the recorded access path (port-forward first if the path is in-cluster — see `discovery.md`): Prometheus `/-/ready` **and** the `query=up` smoke test, Grafana `/api/health`, Loki/Tempo `/ready`, Elasticsearch/OpenSearch `/_cluster/health`, CloudWatch a lightweight `aws cloudwatch list-metrics --max-items 1` | probe healthy — for Prometheus the smoke test must return data, not just `/-/ready` |

Stamp `✓ verified <today>` **only on the specific fact the check actually
proved** — context/namespace/workload existence, image tag, endpoint health.
Fields the check does not probe — region, cloud account, access
limitations/RBAC notes, GitOps manager — keep their prior status; never
re-stamp them verified from an existence check. Re-confirm an access limitation
or GitOps ownership only by observing it this run. A failed check → mark the
fact `⚠ needs verification`, add to §6 Known unknowns, and route it to Phase 2
for real re-discovery.

## Update rules (end-of-run write-back)

Runs **at end of run**, after the investigation completes — so §3 captures
what was actually investigated (dashboards, alerts, GitOps manager, owner,
dependencies) rather than a half-filled row committed mid-incident. Writing the
memo is a local-documentation update, not a change to the incident target, so
it is exempt from the read-only-until-approval gate (Safety rule 1); it never
touches the cluster and stores no secret values.

- **Add** newly discovered structure and any service investigated this run to §3.
- **Verified change** (image bump, new/removed workload, ingress/namespace/
  ownership/dependency change, obs-link change) → update the row **and** append
  one §4 Changelog line.
- **Failed verification** → mark the row `⚠ needs verification`; **do not
  hard-delete**. Remove a fact only once it is confirmed absent (explicitly
  gone), not after a single miss.
- Append exactly one §5 Discovery-history line per run.
- **Verified information only.** Anything inferred but unconfirmed is written
  as `needs verification`, never as fact (the "never guess" rule, applied to the memo).
- Update the `_Last verified:_` date, then write the file. Commit it locally
  **staged and scoped to the memo path with an inline message**:
  `git add docs/sre-agent-memo.md && git commit docs/sre-agent-memo.md -m "chore(sre): update project memo"`.
  Never a bare `git commit` — with no `-m` it blocks on an editor in a
  non-interactive session, and with no pathspec it sweeps any unrelated staged
  changes into the memo commit. **Never push; never add a co-author line.** If
  the working dir is not a git repo, or the memo path has unstaged conflicts you
  would disturb, write the file and tell the user it was left uncommitted rather
  than forcing a commit.

## Edge cases

| Case | Behavior |
| :--- | :--- |
| No memo yet | Cold start — create fresh from `project-memo.template.md`. |
| No cluster access | Memo still usable as hints; mark everything `needs verification`; no deletions. |
| Multiple environments | One memo, per-env rows in §1. |
| Corrupt/unparseable memo | Never overwrite in place. Preserve the original (copy to `docs/sre-agent-memo.bak.md`), surface the problem to the user, and start fresh from the template **only with their acknowledgment** — do not discard accumulated knowledge on an unverified "corrupt" judgment. |
