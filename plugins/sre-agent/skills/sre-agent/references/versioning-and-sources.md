# Versioning & Official Sources

This file pins which sources runtime research may cite during Phase 4
("research solutions") and how skill authors refresh the plugin's content.
Prefer live-system introspection over any document: API responses,
`kubectl explain`, `--help` output, and readiness/health endpoints are
generated by the running system and cannot be stale.

## Baseline snapshot

- Snapshot date: 2026-07-03.
- Prometheus docs baseline: current stable docs on the snapshot date.
- Grafana/Loki/Tempo/Mimir/Alloy docs baseline: `latest` channel on the snapshot date.
- Kubernetes docs baseline: v1.36.
- Flux and Argo CD baselines: current stable docs on the snapshot date.

If the live system reports different versions, state the version you are
answering for and check the release notes before giving field-level advice.

## Version-sensitivity rules

1. Prefer the live system: query the actual Prometheus/Loki/Grafana API,
   run `kubectl explain`, read `--help` output.
2. If offline, state the baseline version assumed and mark the answer as
   version-sensitive.
3. Cite the official source category when giving version-sensitive guidance;
   avoid old blog posts and Stack Overflow unless the task is
   provider-specific.

## Refresh checklist

1. Re-crawl the source baseline table quarterly, or when a major release of
   Prometheus, Grafana, Loki, Kubernetes, Flux, or Argo CD ships.
2. Verify every query in `prometheus-analysis.md` and
   `logs-investigation.md` against the current query-language docs.
3. Verify API paths in `grafana-discovery.md` against current Grafana HTTP
   API docs.
4. Update the baseline snapshot date above.
5. Bump the plugin `version` in both manifests so users receive the refresh.
